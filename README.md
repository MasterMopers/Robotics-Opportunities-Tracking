# Robotics Opportunities Tracker

A running, auto-updating list of **robotics contests you can enter** and **microgrants you can apply for** -- built for solo and small-team builders, not companies or funded startups.

- **Contests** -- hackathons, build challenges, and competition tracks you compete in. Hosted by companies, universities, or event organizers.
- **Grants** -- money you apply for and (if selected) just receive, with no competing and no company required.

Every listing below is pulled automatically from the source's own page and re-checked weekly, so treat it as a starting point -- **always confirm current details on the official page before you apply**, especially the deadline. Location and participant-count fields come from deterministic regex first; only when regex can't find them does a small opt-in LLM fallback (extraction only -- it's instructed to output nothing rather than guess, see below) try to fill the gap. Filters skew toward opportunities realistic for one or two people: no minimum team size beyond a couple people, no "must be a registered company" or "requires a faculty advisor" grants.

<details>
<summary><strong>How this list is generated</strong> (click to expand)</summary>

Everything below `BEGIN AUTOGEN` is regenerated by `render_readme.py` from `state.db` -- do not hand-edit it, it will be overwritten. Everything above and outside that block is hand-written and safe to edit.

`.github/workflows/monitor.yml` runs `monitor.py` weekly (new items -> opens a GitHub issue) and rebuilds this README monthly. See `sources.yaml` for every tracked source and the watch calendar, and `rules.yaml` for the classification and field-extraction rules -- tune both without touching code.

Classification (accept/review/reject, contest-vs-grant) is fully deterministic (regex/keyword rules) and never calls an LLM. Two enrichment fields specifically -- `location` and `participants_count` -- have an *opt-in, fallback-only* assist: `lib/enrich.py`'s regex extractors always run first for free; only when a field is still unresolved does `lib/llm_enrich.py` make a single GPT-5 Nano API call, instructed to extract *only* what the page's own text explicitly states (a structured-output JSON schema forces `null` rather than a guess). This path is entirely gated on an `OPENAI_API_KEY` repository secret -- with no secret set (the default for any fork), behavior is byte-for-byte identical to before this feature existed: zero LLM calls, zero secrets required. When enabled, each run is capped at 25 calls (200 for a manual backfill) so a source bug flooding "new" items can't produce a surprise bill; at this project's real volume (a handful of new items/week) the estimated cost is roughly $0.08-$0.24/year. Any field the LLM fills in is tagged with confidence `"llm"` in `state.db`, so a regex-confirmed fact and an LLM-assisted one are always distinguishable. `python monitor.py --backfill` (also triggerable via a `workflow_dispatch` checkbox on the Actions tab) applies the same regex-first/LLM-fallback logic to already-accepted rows still missing these fields.

This repo is public, so its GitHub Actions minutes are unlimited (a private repo gets 2,000 free minutes/month; this weekly ~2-minute job would be far inside that budget either way).
